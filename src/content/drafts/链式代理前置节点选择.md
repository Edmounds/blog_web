## 如何选择链式代理前置节点
链式代理组成是前置节点+落地节点

前置节点选择的核心逻辑是：充当一条纯粹且透明的 TCP 传输隧道。
许多协议作为直连节点体验良好，但作为前置节点时会导致严重断流或卡死。
### 前置协议选型建议

|   评级    | 协议类型                | 技术特性                       |
| :-----: | :------------------ | :------------------------- |
| **最优选** | **Shadowsocks **    | 纯粹的 TCP 密文字节流，无证书握手与多路复用干扰 |
| **推荐**  | **Trojan (原生 TCP)** | 单层标准 TLS 加密隧道，握手干净标准       |
| **推荐**  | **VMess (纯 TCP)**   | 基础对称加密传输（禁用 WS，禁用 CDN）     |
| **避坑**  | **Hysteria / TUIC** | 基于 UDP / QUIC 协议栈          |
| **避坑**  | **VLESS-Reality**   | XTLS-Vision 流控检查与证书偷取机制    |
| **避坑**  | **任何套 CDN 的节点**     | 经过 Cloudflare 等边缘反代        |

在结合协议后考虑延迟、地区
地区这里简单说说，就是选择物理链路最短的组合。假设你的家宽落地节点在美西，你不能选一个欧洲或者印度的节点吧，不然物理上就会增加很多没必要的延迟。在大陆最好选择香港、日本、新加坡这种节点，一般是后续都是通过太平洋海底光缆到美西。

省流就是选择合适协议的低延迟亚太节点作为前置节点
### 为什么高级协议做前置极易断流？

1. **UDP / QUIC 协议无法稳定嵌套**
客户端通过 UDP 隧道嵌套 TCP 家宽握手，底层状态机处理繁琐。双层拥塞控制相互竞争冲突，导致连接频繁重置。
**涉及协议**：Hysteria 1/2、TUIC、WireGuard。

2. **Reality / Vision 流控与内层握手冲突**
Reality 模拟真实网站的 TLS 握手。隧道内部嵌套二次代理握手（如 SOCKS5 或二次 TLS）会污染流量特征，触发 Vision 模块的流控过滤阻断，直接向客户端返回 RST。
**涉及协议**：VLESS-Reality、VLESS-XTLS-Vision。

3. **WebSocket + CDN 超时掐断**
CDN 边缘节点有严苛的回源连接超时限制。前置连接慢速家宽网关超时，CDN 直接返回 502 或 504 Gateway Timeout。
**涉及协议**：套用 Cloudflare CDN 的 WS 或 gRPC 节点。

## 前置节点常见协议对比

前置链路运行在公网审查与内网监控环境中，核心关注加密强度与防审计能力。

| 协议 / 类型               | 传输层        | 加密情况                               | 伪装与抗阻断能力                     |
| :-------------------- | :--------- | :--------------------------------- | :--------------------------- |
| **HTTP Proxy**        | TCP        | **无加密**                            | 无伪装。纯明文文本，网关直接正则匹配           |
| **SOCKS5**            | TCP / UDP  | **无加密**                            | 无伪装。固定十六进制握手特征 (`05 01 00`)  |
| **Shadowsocks**       | TCP / UDP  | **对称强加密** (AES-256-GCM / ChaCha20) | 纯随机密文。无协议明文字段，但易被特征库匹配       |
| **VLESS-Reality**     | TCP        | **TLS 1.3 强加密**（公钥认证）              | 极高。借用外部真实网站 SNI，消除证书特征       |
| **Trojan**            | TCP        | **标准 TLS 1.3 加密**（CA 证书）           | 高。密码塞入 TLS 正文，表现与合法 HTTPS 一致 |
| **Hysteria 2 / TUIC** | UDP (QUIC) | **TLS 1.3 强加密**                    | 伪装为 HTTP/3 流量或随机 UDP 数据      |
> 注意，HTTP 代理不包含传输层加密。中间网络设备直接抓包读取请求头、完整 URL 路径、Cookie 与账号凭证
