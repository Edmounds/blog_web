## 如何選擇鏈式代理前置節點
鏈式代理由前置節點＋落地節點組成

選擇前置節點的核心原則是：讓它充當純粹且透明的 TCP 傳輸隧道。
許多協定作為直連節點時體驗良好，但作為前置節點時，可能會導致嚴重斷流或卡死。
### 前置協定選擇建議

|   評級    | 協定類型                | 技術特性                       |
| :-----: | :------------------ | :------------------------- |
| **首選** | **Shadowsocks **    | 純粹的 TCP 加密位元組流，不受憑證握手與多路複用干擾 |
| **推薦**  | **Trojan (原生 TCP)** | 單層標準 TLS 加密隧道，握手乾淨且符合標準       |
| **推薦**  | **VMess (純 TCP)**   | 基礎對稱式加密傳輸（停用 WS，停用 CDN）     |
| **避免使用**  | **Hysteria / TUIC** | 基於 UDP / QUIC 協定堆疊          |
| **避免使用**  | **VLESS-Reality**   | XTLS-Vision 流量控管檢查與憑證竊取機制    |
| **避免使用**  | **任何套用 CDN 的節點**     | 經過 Cloudflare 等邊緣反向代理        |

選定協定後，再考量延遲與地區。
簡單談談地區選擇：挑選實體鏈路最短的組合即可。假設你的家用寬頻落地節點在美西，總不會選歐洲或印度的節點吧？否則在實體上就會增加許多不必要的延遲。在中國大陸，最好選擇香港、日本、新加坡等地的節點，後續一般都會透過太平洋海底光纜連到美西。

簡單來說，就是選擇協定合適、延遲低的亞太節點作為前置節點。
### 為什麼進階協定作為前置節點時特別容易斷流？

1. **UDP / QUIC 協定無法穩定巢狀封裝**
用戶端透過 UDP 隧道巢狀封裝 TCP 家用寬頻握手，底層狀態機的處理十分繁瑣。雙層擁塞控制彼此競爭、互相衝突，導致連線頻繁重設。
**涉及協定**：Hysteria 1/2、TUIC、WireGuard。

2. **Reality / Vision 流量控管與內層握手衝突**
Reality 會模擬真實網站的 TLS 握手。隧道內再巢狀封裝第二次代理握手（例如 SOCKS5 或第二次 TLS），會污染流量特徵，觸發 Vision 模組的流量控管過濾並阻斷連線，直接向用戶端回傳 RST。
**涉及協定**：VLESS-Reality、VLESS-XTLS-Vision。

3. **WebSocket + CDN 因逾時而中斷**
CDN 邊緣節點對回源連線的逾時限制相當嚴格。若前置連線至速度較慢的家用寬頻閘道器時逾時，CDN 就會直接回傳 502 或 504 Gateway Timeout。
**涉及協定**：套用 Cloudflare CDN 的 WS 或 gRPC 節點。

## 前置節點常見協定比較

前置鏈路運作於公網審查與內網監控環境中，核心考量是加密強度與防止稽核的能力。

| 協定 / 類型               | 傳輸層        | 加密情況                               | 偽裝與抗封鎖能力                     |
| :-------------------- | :--------- | :--------------------------------- | :--------------------------- |
| **HTTP Proxy**        | TCP        | **無加密**                            | 無偽裝。純明文內容，閘道器可直接以正規表示式比對           |
| **SOCKS5**            | TCP / UDP  | **無加密**                            | 無偽裝。固定的十六進位握手特徵 (`05 01 00`)  |
| **Shadowsocks**       | TCP / UDP  | **強對稱式加密** (AES-256-GCM / ChaCha20) | 純隨機密文。沒有協定明文字段，但容易被特徵資料庫比對       |
| **VLESS-Reality**     | TCP        | **TLS 1.3 強加密**（公鑰驗證）              | 極高。借用外部真實網站的 SNI，消除憑證特徵       |
| **Trojan**            | TCP        | **標準 TLS 1.3 加密**（CA 憑證）           | 高。將密碼置於 TLS 內文中，呈現方式與合法 HTTPS 一致 |
| **Hysteria 2 / TUIC** | UDP (QUIC) | **TLS 1.3 強加密**                    | 偽裝成 HTTP/3 流量或隨機 UDP 資料      |
> 注意，HTTP 代理不包含傳輸層加密。中間網路設備可以直接攔截封包，讀取要求標頭、完整 URL 路徑、Cookie 與帳號憑證
